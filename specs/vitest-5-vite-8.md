# Move the unit-test toolchain to vitest 5, @vitejs/plugin-react 6 and vite 8

**Go:** "To merge all the open PRs of the Pendabot. Can you manage all of that? Answer anything that has to be done in there and get it done on a new session or multiple new sessions. Just go and open them. Don't come to me." (owner, 2026-11-10)

## Intent

The owner asked for every open Dependabot PR to be merged, and for whatever they need to be done
without coming back to them. Two of them can't pass alone: #12 (`@vitejs/plugin-react` 5.2.0 →
6.2.1) fails to load the test config because plugin-react 6 needs vite 8 and vitest 4 brings vite
7 (`Package subpath './internal' is not defined by "exports"`); #14 (vitest 4.1.5 → 5.1.0) fails
the UI package's typecheck because jest-dom's matchers are missing from vitest 5's assertion type
(`Property 'toHaveAttribute' does not exist on type 'Assertion<void, HTMLElement>'`). This change
moves the three together, fixes the types, and supersedes #12 and #14. No app code changes.

## Decisions

- One PR for vitest, plugin-react and vite: plugin-react 6 requires vite 8, and vitest 5 accepts
  vite 8 (`^6.4.0 || ^7.0.0 || ^8.0.0`), so they land together; rejected: two PRs, each red without
  the other (Claude, 2026-11-10).
- `vite` becomes an explicit dev dependency (`^8.2.6`) of `apps/web` and `packages/ui`, the two
  packages that use plugin-react, so its peer is met and vitest resolves the same vite; rejected: a
  root `pnpm.overrides`, which would hide the requirement (Claude, 2026-11-10).
- jest-dom's matchers are added to vitest 5's `Matchers<R, T>` in `packages/ui/vitest.setup.ts`,
  the file that already loads them: jest-dom 6.9.1, and 7.0.1 too, still augments the old
  one-parameter `Assertion<T>`, which vitest 5's `Assertion<R, T>` no longer merges with; rejected:
  moving to jest-dom 7, whose types are the same. To remove once jest-dom ships vitest 5 types
  (Claude, 2026-11-10).
- `packages/ui` declares `@types/node` (`^26`, as `apps/web` and `packages/core` do). Without it,
  pnpm resolves vitest's optional `@types/node` peer for that package on its own, and a lockfile
  regenerated by Dependabot (#8, #10, #13) gave it 25.9.9 beside the others’ 25.6.0: two copies of
  vitest, and the UI package's inline snapshot failed with "The snapshot state … is not found".
  With it, every package shares one vitest; rejected: leaving it to whichever lockfile wins
  (Claude, 2026-11-10).
- Our own branch instead of pushing to Dependabot's: the bump needs a code change; #12 and #14 are
  closed with a link here (Claude, 2026-11-10).

## Acceptance items

- **AC-1** `apps/web`, `packages/ui` and `packages/core` ask for `vitest` `^5.1.0`; `apps/web` and
  `packages/ui` ask for `@vitejs/plugin-react` `^6.2.1` and `vite` `^8.2.6`; `packages/ui` asks for
  `@types/node`; the lockfile holds one vitest and one vite — verified by review: the diff and
  `pnpm-lock.yaml`.
- **AC-2** Every package's unit tests load their config and pass under vitest 5, including the
  UI package's inline snapshots — verified by review: `fast`'s `test:unit` green.
- **AC-3** The UI package typechecks with jest-dom's matchers (`toBeDisabled`,
  `toHaveTextContent`, `toHaveAttribute`, `toBeInTheDocument`) on vitest 5's `expect` — verified
  by review: `fast`'s typecheck green on `packages/ui/src/LoadingArea.test.tsx` and
  `SubmitButton.test.tsx` unchanged.

## Out of scope

- Vitest 5's suggestion to share one jsdom per worker (`pool: 'vmThreads'` or `isolate: false`):
  a speed change to the test setup, not needed for the bump.
- Playwright and the integration-test configuration.
